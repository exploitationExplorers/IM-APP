# iOS 图片保存与群聊滚动修复

记录时间：2026-11-17T10:01:41+08:00。本轮修订 **20261117-ui3**，代码未提交、未推送。

## 修改与依据

- 图片预览和气泡菜单统一走同一导出逻辑。原先直接把无扩展名的下载临时文件交给 Photos；现在用 ImageIO 检测实际格式，生成扩展名、UTI、originalFilename 一致的独立资源，并保留至相册事务完成。PNG/JPEG/HEIC/HEIF/GIF/TIFF 保留原文件字节；静态 WebP 转 PNG 保留透明度，动态 WebP 转 GIF 保留帧、时长和循环次数，并限制转换资源消耗。坏文件先报明确错误。
- 群聊原先以 72 点估算全部消息高度，随后由长文本/媒体自动改高；同时迟到的首屏历史请求会再次要求滚到底部。现在按相同的气泡尺寸逻辑预先测量并缓存实际行高，历史插入按可见消息锚点恢复位置，快照串行应用。图片比例回调只上报变化，尺寸更新避开拖动与惯性滚动；迟到的首屏不打断已开始阅读的用户。
- 修正历史刷新任务完成后未清空的问题，避免后续自动翻页被残留任务挡住。

截图可确认 Photos 报 3302，但尚未取得这张原图的实际文件；不能仅凭截图证明具体资源格式或唯一根因。上述修复覆盖了已发现的资源命名和滚动逻辑缺陷，仍需运行验收。
