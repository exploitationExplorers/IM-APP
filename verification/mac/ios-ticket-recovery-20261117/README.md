# 单账号 iOS 票据恢复与故障归因

核验日期：2026-11-17（Asia/Shanghai）。

## 已确认的直接原因

这次特定测试账号无法登录聊天的直接原因是业务后端票据缓存与 OpenIM 的有效票据状态不一致。业务密码登录成功，但业务取票接口重复返回同一张平台 1（iOS）票据；业务 Redis 也持有这张票据，缓存期限仍在未来。OpenIM 对该票据返回 1507（TokenNotExistError）。绕过模拟器、SDK 和 UI 的独立请求也复现了拒绝。

同账号平台 2（Android）的票据有效，因此安卓正常与 iOS 失败可以同时发生。另一个对照账号的平台 1、2 均正常。证据不支持把这个账号的认证阻塞归因为密码长度、旧模拟器安装包或已证实的 SDK 缺陷。

最初是什么操作或流程使旧票据不再有效，尚未查明。已确认的是后端仍持续缓存并返回这张失效票据；定点修复没有解决自动发现、重签和避免复发的长期机制。

## 授权范围与实际操作

用户授权仅恢复失败测试账号的平台 1 票据及其对应业务缓存。经现有管理通道，使用现有管理员身份调用 OpenIM 官方签发接口，只为该用户的平台 1 取得有效票据；校验通过后，以旧缓存值精确比较并原子替换对应 Redis 项。实际更新 1 项。

没有部署代码、重启服务、修改多端策略、删除用户数据、发送消息或改变其他账号。Android 票据与原值相同且仍有效。业务 API 与 OpenIM 容器的镜像、ID、启动时间在操作前后相同。用户此前“暂不部署”的决定继续有效。

## 验证限制与下一步

本次通过的是服务端票据和会话接口验证，没有在原生 App 内完成新的 SDK 在线连接或逐页 UI 验收。用户需退出该测试账号后重新登录，让 App 取得已恢复的票据。页面布局、保存图片、群聊滚动闪动仍需分别在 App 中复核，不能据此宣布全部修复。

本轮没有修改 App 或后端源代码，也没有新构建、提交或推送。此前的本地修复和测试结果属于之前工作阶段。本次恢复属于定点运维修复；后端自动校验失效缓存并重签的持久修复尚未部署。
