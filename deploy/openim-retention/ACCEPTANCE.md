- [ ] 052–055 增量迁移已在独立数据库验证，正确配置 OSS 媒体白名单，未改变生产稳定签名密钥。

- [ ] 桥仅在私网可达；无公网端口/反代；v2 与专用 key 一致；错误 key 不返回数据。
- [ ] 新版本逻辑 worker 默认开启全群。过渡部署/桥未准备好时须显式 `off`；先隔离环境测试，再只配置一个专用业务群 UUID 并设 `GROUP_RETENTION_ALL_GROUPS=false`，确认不会领取名单外旧任务，验收后再恢复全群默认策略。缺少私网桥配置必须报错，不能假报已开启。

- [ ] H5、iPhone、Android 使用确切新版本；WGT appid、资源版本、原生最低版本及渠道与目标壳匹配。
- [ ] OSS 生命周期未覆盖头像、收藏、转发副本或整个聊天前缀；删除权限仅新 managed-v1 前缀；版本控制未开启过；激活探针通过。

## 功能验收矩阵

每项分别记录 H5 桌面、H5 手机视口、iPhone、Android 的版本、时间、群/会话标识、结果。只在独立测试库造数据，不能向现有生产群批量灌消息。

| 场景 | 预期 |
| --- | --- |
| 登录、文字、图片、视频、语音、文件、头像上传 | 与原功能兼容，新上传仍走 OSS；新头像/语音目录正确，旧文件保留 |
| 0/1499/1500/1501 条可见群消息 | 1501 条清理后恰好保留最新 1500（可后台改配额）；不是按序号差计算 |
| 168 小时前/恰好/后 | 恰好边界保留；超时即使不足配额条数也过期 |
| 隐藏控制、可见群通知、已撤回/删除 | 不可见控制不占配额；展示通知占条数；不会跨群/跨单聊 |
| 历史超过 20,000 条，最新尾部连续可判定 | 只读尾部证明最近配额条数后应用，不因总历史大而跳过 |
| 尾部未落库空洞、未知类型、非前缀过期 | 任务退避/阻塞，不假报成功，不越过保留消息强删 |
| 清理时同群持续发送、转存积压、进程崩溃/重启 | 不删固定水位之外的新消息；租约到期重试，旧 worker 不提交新状态 |
| 多业务副本并行、同群跨日任务 | 日任务幂等，ACK/水位单调，旧 ACK 不回退 |
| 仅允许测试群，库里存在其他群的旧排队/已规划任务 | 入队、规划和应用均不越出名单；移出名单不会使已清理旧消息再出现 |
| 未设置开关/范围、显式暂停、缺少桥配置 | 新发布默认全群 visibility_only 及受控 GC；暂停不移除引用围栏；缺 URL/key 拒绝启动，不回退假开启；物理正文清理仍关闭 |
| 群收藏后源消息过期 | 收藏里的图片/视频封面/语音/文件正常；新收藏独立副本已完成才返回成功 |
| 群媒体转发到单聊/另群，引用及嵌套合并 | 先归档再发送；源群逻辑过期后目标内容正常；复制失败不发送坏链接 |
| 旧收藏补偿，存在源 404 和正常源混合 | 正常项仍处理；404 项不伪造完成；重启/重扫不重复建记录 |
| 队列旧待发转发任务补偿 | 投递前补副本，失败退避；同幂等键重试不重复发送 |
| 已打开群，日清理边界推进 | 在线轮询后列表/原始消息/摘要中过期项消失，不再响铃/震动 |
| 搜索、定位、媒体列表、最后消息、@提示 | 不能从本机或服务端搜索重新翻出过期项；独立收藏和引用内容仍可打开 |
| 清理后未读数及其他群/单聊 | 过期前缀不再计入，不把剩余有效消息一并标为已读；其他会话不变 |
| 手机离线→清理→回到前台/重连/重新登录 | 成功同步水位后旧历史不复活，旧 SDK 本地回调不覆盖 tombstone |
| 清本地业务缓存、退出重登、切账号、超过 5000 群 | tombstone 保留且按账号隔离，无旧响应串号，无静默 LRU 丢弃 |
| 新发送、原生 seq 延迟回执、随后清历史/切账号、旧会话摘要事件 | 摘要文案与 ID/seq 属于同一条消息；旧回执不覆盖新摘要、不重新插入已清消息或串号 |
| 暂停逻辑/GC 任务、旧的更小 ACK/水位 | 已应用历史仍隐藏，不复活；引用保护保留；不恢复已经删除的文件 |
| 正文 worker 默认关闭，GC 开启 | Mongo 正文保留；只有满足全部证据/缓冲的无引用 managed-v1 对象可被删除；旧对象不扫 |
| 另行验收开启指定测试群正文 worker | 首次 ACK 至少 24 小时后清理过期槽位；保留文档/索引布局、有效尾部、单聊和其他群 |
| 正文清理与积压转存并发、晚到首次插入/撤回、崩溃重启 | 原子 fence 防正文复活；不陷入 duplicate-key 重试；持久化游标有限续跑 |
| 源消息正文清理后打开引用、合并转发和收藏 | 内嵌快照/独立副本可用，不被源消息缺失误判为撤回；OSS 文件仍在 |
