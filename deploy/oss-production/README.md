## 第一步：只读核对后端

将本目录 `inspect-production-oss.py` 上传至 **后端 `8.154.44.197`** 宝塔“文件”中的 `/tmp/inspect-production-oss.py`，然后在该后端宝塔终端执行：

```bash
python3 /tmp/inspect-production-oss.py
```

脚本固定后端 hostname 和本机 Docker socket，忽略 Docker 连接环境覆盖；只读取生产容器的镜像、状态、Compose 路径、卷/端口、两个 OpenIM 配置文件的指纹和对象引擎字段，以及 PostgreSQL 表结构。数据库查询使用只读会话并设置超时，不读取业务记录。不会输出环境变量原文、数据库 URL、配置正文、密钥或聊天内容；不启动/停止服务、不备份、不迁移、不访问 OSS。若缺权限或文件缺失，保留现场，不改配置来绕过。

把 `IM_APP_PRODUCTION_OSS_INVENTORY_BEGIN` 至结果标记之间的输出返回。`INVENTORY_OK` 只表示检查完成，不表示 OSS 已上线。脚本输出是容器/表结构元数据，也不要公开到无关渠道。

## 后续接入顺序

1. 按实际镜像/配置/现有表结构制作精确变更清单。当前仓库中的 OpenIM 适配层限于本机测试配置，不能直接用于正式库。
2. 在服务器私密目录备份 PostgreSQL、OpenIM MongoDB 和当前配置/镜像引用，核对备份可恢复。备份不发聊天、不入 Git。原 MinIO、卷和公网旧路由持续保留。
3. 补齐并验证 OpenIM 的兼容读取：新上传/元数据写 OSS；旧 `engine=minio` 映射和直链继续从 MinIO 读。不批量更改历史 Mongo 映射、消息正文或文件 URL，不清空 Redis。哈希复用、缓存、上传中的分片以及回退后新 OSS 文件读取均须覆盖。
4. 业务文件已按任务 provider/bucket 固定存储。增量 SQL 只增加 `files.storage_provider/storage_bucket`，旧记录按 MinIO 解释。正式执行前设置短 `lock_timeout/statement_timeout`，加锁失败则整批回滚，不等待拖住现有请求。实际执行单在盘点和备份后提供；此目录不附一键执行入口。
5. 业务新进程使用 `APP_ENV=oss-production`、`MIGRATIONS_MODE=verify`、`SEED_DEMO=false`。程序在连接数据库前检查这些约束；启动只校验必需列，不重跑历史迁移。普通模式仍保留自动迁移，禁止用普通启动命令替代本次受控更新。管理服务本次不因 OSS 存储切换而自动重启。
6. 复用现有两个香港桶和 RAM，核对拟使用的正式新增对象前缀授权、HTTPS/CORS 与私有读取。现有域名名称含 `test` 不决定数据性质；实际用于正式新上传后即承载正式数据，必须持续保管和续签，不能按测试对象清理。不要直接复用本机启动器/测试 `.env`，不要改变旧前缀含义。
7. 按窗口先验证业务上传/历史文件，再切聊天上传；客户端继续连接现有服务。先用少量受控账号验证新上传、历史消息、转发、收藏、视频/语音、冷启动和实时收发，记录停止条件。不能承诺服务切换绝对无连接抖动。
8. 前端确有必要时再走原有 WGT 渠道，核对包内 API/channel/AppID 和版本，先内部真机验证，再扩大范围；仅发布 canary 不会使请求 `test` 的现有包自动收到更新。

## 数据保护与回退边界

- 本轮不复制/删除旧对象，不启用“7 天/500 条”清理，不新增共享桶生命周期，不更改群/用户/消息数据来配合存储迁移。
- 回退的是新上传目标，不能回退到完全不认识 OSS 的旧读取代码；已写入 OSS 的文件必须继续可读。新对象对应的稳定签名 key 和 URL 持久保留。
