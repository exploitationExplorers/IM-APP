# 万人转发后端接口与队列

## 约定

- 一个任务的目标总数不设业务上限。
- 每次手工增删目标最多提交 1000 个 ID，这是 HTTP/数据库写入批次，不是任务人数上限；可重复调用，或使用服务端条件生成。
- GET 参数使用 query；所有新增 POST 接口只接收 JSON body，不在 URL 路径拼参数。
- 旧 `GET /api/v1/forward-tasks/:id` 继续保留兼容。
- 当前不做前端接入，也不做离线推送。Worker 调 OpenIM 时固定 `notOfflinePush=true`。

## 任务流程

1. `POST /api/v1/forward-tasks` 创建草稿，并冻结源消息内容。
2. 调用目标 add/generate 接口，可分任意多批持续添加。
3. `POST /api/v1/forward-tasks/submit` 提交。
4. 同一数据库事务写入任务状态与 outbox，outbox publisher 将任务事件发送到 Kafka。
5. Kafka consumer 每次按 `FORWARD_BATCH_SIZE` 领取一批目标，按 `FORWARD_QPS` 节流逐个发送。
6. 当前批次完成后先发布下一批 Kafka 事件，再显式提交当前 consumer offset。
7. 通过进度和目标列表查询成功、失败、跳过、取消数量；失败任务可重试。

Kafka 是实际的任务调度队列，PostgreSQL 不轮询发送目标，只保存任务状态、目标进度、幂等数据和 Kafka 事务 outbox。outbox 用来解决“数据库提交成功但 Kafka 发布失败”的双写问题，不承担消息消费。

消费语义为 at-least-once。服务重启不会丢任务；领取目标带数据库租约，进程异常退出后，租约超时目标可由 Kafka consumer 重新领取。每个目标使用确定性的 `clientMsgID`，用于降低重复消费产生重复消息的风险。

Kafka 未配置时，提交、恢复、重试接口返回 503，不会静默回退成 PostgreSQL 队列。

## 接口

| 方法 | 路径 | 参数位置 | 作用 |
|---|---|---|---|
| POST | `/api/v1/forward-tasks` | body | 创建草稿，可同时带首批 `targetUserIds` |
| GET | `/api/v1/forward-tasks` | query | 任务分页，支持 `status,cursor,limit` |
| GET | `/api/v1/forward-task-progress` | query | `taskId` 查询进度 |
| GET | `/api/v1/forward-task-targets` | query | `taskId,status,cursor,limit` 查询目标明细 |
| POST | `/api/v1/forward-task-targets/add` | body | 分批添加好友目标 |
| POST | `/api/v1/forward-task-targets/generate` | body | 按全部好友、标签或搜索条件生成目标 |
| POST | `/api/v1/forward-task-targets/remove` | body | 草稿阶段分批移除目标 |
| POST | `/api/v1/forward-task-targets/clear` | body | 清空草稿目标 |
| POST | `/api/v1/forward-tasks/submit` | body | 提交执行 |
| POST | `/api/v1/forward-tasks/pause` | body | 暂停领取新目标 |
| POST | `/api/v1/forward-tasks/resume` | body | 恢复任务 |
| POST | `/api/v1/forward-tasks/cancel` | body | 取消未发送目标 |
| POST | `/api/v1/forward-tasks/retry` | body | 重试终态任务里的失败/跳过目标 |

## 主要请求示例

创建草稿：

```json
{
  "sourceConversationId": "si_xxx_yyy",
  "sourceClientMsgId": "source-client-msg-id",
  "sourceServerMsgId": "source-server-msg-id",
  "sourceSnapshot": {
    "contentType": 101,
    "content": { "content": "需要转发的文本" }
  },
  "idempotencyKey": "由调用方生成且重试保持不变",
  "targetUserIds": []
}
```

服务端生成全部好友目标：

```json
{
  "taskId": "任务 UUID",
  "selector": { "mode": "all_friends" }
}
```

也可使用 `mode: "tags"` 并传 `tagIds`，或使用 `mode: "search"` 并传 `keyword`。

提交、暂停、恢复统一 body：

```json
{ "taskId": "任务 UUID" }
```

重试：

```json
{
  "taskId": "任务 UUID",
  "onlyFailed": true,
  "targetUserIds": []
}
```

`targetUserIds` 为空表示重试符合条件的全部目标。

## 状态

任务状态：`draft`、`pending`、`processing`、`paused`、`completed`、`partially_completed`、`failed`、`cancelled`。

目标状态：`pending`、`processing`、`retrying`、`success`、`failed`、`skipped`、`cancelled`。

目标发送前会再次校验双方账号、好友关系和拉黑关系。已删除好友、停用账号或拉黑关系会记为 `skipped`，不会拖住整个任务。
