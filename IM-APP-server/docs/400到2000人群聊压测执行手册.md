# 400～2000 人群聊压测执行手册

本文用于在 Linux 测试服务器上重复执行 400、600、800、1000、1200、1400、1600、1800、2000 人群消息压测。

核心结论：测试群已经拥有至少 2000 名有效成员，并且这些成员已经同步到 OpenIM 时，后续测试只需要修改人数，其他参数不用重新生成。

`-clients` 表示本次建立的真实 OpenIM WebSocket 在线连接数，不会自动注册用户，也不会自动给群添加成员。例如群里只有 1000 名有效成员时，直接改成 2000 会得到 `group has 1000 active members, need 2000`，必须先把测试群准备到 2000 人。

## 零、本次压测使用哪些账号和哪个群

### 1. 消息发送账号

压测消息不是用某个手机号登录 App 后发送的。`groupload` 调用 OpenIM 服务端接口发送消息，发送者取 `.env` 中的 `OPENIM_ADMIN_USER`，本项目默认是：

```text
imAdmin
```

可以在服务器上确认实际值：

```bash
grep '^OPENIM_ADMIN_USER=' .env || echo '未单独配置，程序默认使用 imAdmin'
```

### 2. 在线接收账号

`run_group_load 400` 不是只使用一个接收账号，而是从指定测试群里选择 400 名有效业务用户，分别获取 OpenIM token，并建立 400 条真实 WebSocket 连接。选择顺序与程序一致：群主优先、管理员其次、普通成员最后，同一角色再按入群时间和用户 UUID 排序。

如果测试账号确实是使用仓库的 `prepare-im-users.sh` 默认配置生成的，手机号从 `19900000000` 开始；理论范围如下，但最终必须以数据库查询结果为准：

| 压测人数 | 默认测试手机号理论范围 |
| ---: | --- |
| 400 | `19900000000`～`19900000399` |
| 600 | `19900000000`～`19900000599` |
| 800 | `19900000000`～`19900000799` |
| 1000 | `19900000000`～`19900000999` |
| 1200 | `19900000000`～`19900001199` |
| 1400 | `19900000000`～`19900001399` |
| 1600 | `19900000000`～`19900001599` |
| 1800 | `19900000000`～`19900001799` |
| 2000 | `19900000000`～`19900001999` |

如果创建测试数据时改过 `PHONE_PREFIX`、群里混有其他用户，或者成员入群顺序不同，上述号码范围就不准确。不要凭号码猜测，使用本节后面的数据库命令生成实际账号清单。

### 3. 测试群

400～2000 人各档必须使用同一个已准备好的测试群。准确群公开 ID 可直接从刚才的 400 人报告中读取，不需要重新猜：

```bash
LATEST_400_REPORT="$(find /tmp/loadtest -type f -name 'steady-400-report.json' -printf '%T@ %p\n' \
  | sort -nr | head -n 1 | cut -d' ' -f2-)"

jq '{groupPublicId,openIMGroupId,requestedClients,connectedClients,pass}' "$LATEST_400_REPORT"
export LOAD_GROUP_PUBLIC_ID="$(jq -r '.groupPublicId' "$LATEST_400_REPORT")"
echo "本轮固定测试群公开 ID：$LOAD_GROUP_PUBLIC_ID"
```

其中：

- `groupPublicId`：业务群公开 ID，后续传给 `-group`。
- `openIMGroupId`：同一个群在 OpenIM 中的 groupID，用于排查 OpenIM 日志。
- 群名称不在压测报告中，需要从业务数据库查询。

### 4. 查询群名称、群主和有效成员数

确认 `LOAD_GROUP_PUBLIC_ID` 已按上一步设置，然后执行：

```bash
docker exec -e PGPASSWORD=im123456 im-app-postgres \
  psql -U im -d im_app -v group_public_id="$LOAD_GROUP_PUBLIC_ID" -P pager=off -c "
SELECT
  g.name AS group_name,
  g.public_id AS group_public_id,
  REPLACE(g.id::text, '-', '') AS openim_group_id,
  owner.phone AS owner_phone,
  owner.public_id AS owner_public_id,
  COUNT(gm.user_id) FILTER (WHERE COALESCE(u.status, 'active') = 'active') AS active_members
FROM groups g
JOIN users owner ON owner.id = g.owner_id
LEFT JOIN group_members gm ON gm.group_id = g.id
LEFT JOIN users u ON u.id = gm.user_id
WHERE g.public_id = :'group_public_id'
GROUP BY g.id, g.name, g.public_id, owner.phone, owner.public_id;
"
```

如果数据库容器名、账号或密码不同，按服务器实际配置修改。开始 2000 人测试前，查询结果中的 `active_members` 必须不少于 2000。

### 5. 导出本群实际参与账号清单

下面会按照压测程序的真实选择顺序导出前 2000 名账号，不包含密码和 token：

```bash
mkdir -p /tmp/loadtest
docker exec -e PGPASSWORD=im123456 im-app-postgres \
  psql -U im -d im_app -v group_public_id="$LOAD_GROUP_PUBLIC_ID" -P pager=off -c "
COPY (
  SELECT
    ROW_NUMBER() OVER (
      ORDER BY CASE gm.role WHEN 'owner' THEN 0 WHEN 'admin' THEN 1 ELSE 2 END,
               gm.joined_at,
               u.id
    ) AS client_no,
    gm.role,
    u.phone,
    u.public_id,
    REPLACE(u.id::text, '-', '') AS openim_user_id
  FROM group_members gm
  JOIN groups g ON g.id = gm.group_id
  JOIN users u ON u.id = gm.user_id
  WHERE g.public_id = :'group_public_id'
    AND COALESCE(u.status, 'active') = 'active'
  ORDER BY CASE gm.role WHEN 'owner' THEN 0 WHEN 'admin' THEN 1 ELSE 2 END,
           gm.joined_at,
           u.id
  LIMIT 2000
) TO STDOUT WITH CSV HEADER;
" > /tmp/loadtest/group-test-accounts.csv

wc -l /tmp/loadtest/group-test-accounts.csv
head -n 6 /tmp/loadtest/group-test-accounts.csv
tail -n 5 /tmp/loadtest/group-test-accounts.csv
```

CSV 第一行是表头，因此 2000 名参与账号对应 `wc -l` 输出 `2001`。九档测试分别使用清单中的前 400、600、800、1000、1200、1400、1600、1800、2000 名账号。

## 一、每次登录服务器后进入目录

```bash
cd ~/IM-APP/IM-APP-server
pwd
```

后面的所有命令都必须在 `IM-APP-server` 根目录执行，这样程序才能读取当前目录中的 `.env`。

## 二、首次只编译一次

代码没有更新时，不需要每次使用 `go run` 重新编译。

```bash
mkdir -p .tmp/bin
go build -o .tmp/bin/groupload ./cmd/groupload
chmod +x .tmp/bin/groupload
```

检查程序：

```bash
./.tmp/bin/groupload -h
```

以后只有拉取了包含 `cmd/groupload` 改动的新代码，才需要重新执行本节的编译命令。

## 三、每个 SSH 终端只设置一次固定参数

如果已经按“零、本次压测使用哪些账号和哪个群”从 400 人报告中读取了 `LOAD_GROUP_PUBLIC_ID`，这里不要再次修改它。先确认：

```bash
echo "$LOAD_GROUP_PUBLIC_ID"
```

只有找不到原 400 人报告时，才手工填写之前命令中 `-group` 后面的群公开 ID。不要填写数据库内部 UUID 或 OpenIM groupID：

```bash
export LOAD_GROUP_PUBLIC_ID='替换成测试群公开ID'
```

其余固定连接参数每个 SSH 终端设置一次：

```bash
export LOAD_DATABASE_URL='postgres://im:im123456@127.0.0.1:5433/im_app?sslmode=disable'
export LOAD_OPENIM_API_URL='http://127.0.0.1:10002'
export LOAD_OPENIM_WS_URL='ws://127.0.0.1:10001'
export LOAD_OPENIM_CONTAINER='openim-server'
```

如果服务器的数据库账号、端口、OpenIM 地址或容器名不同，只在这里改一次。当前仓库新版 OpenIM 容器名可能是 `im-openim-api`；可用下面的命令确认：

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

## 四、每个 SSH 终端只加载一次通用函数

整段复制执行一次。它会自动创建带时间戳的结果目录，保存 JSON 报告、程序日志、Docker 资源快照、宿主机 `vmstat` 和 OpenIM 异常日志。

```bash
run_group_load() {
  local clients="${1:?用法: run_group_load 人数}"

  if ! [[ "$clients" =~ ^[0-9]+$ ]] || (( clients < 1 || clients > 4000 )); then
    echo '人数必须是 1～4000 的整数' >&2
    return 2
  fi
  if [[ -z "${LOAD_GROUP_PUBLIC_ID:-}" ]]; then
    echo '请先设置 LOAD_GROUP_PUBLIC_ID' >&2
    return 2
  fi

  local stamp run_id result_dir report_file runner_log resources_log host_log openim_log
  local started_at vmstat_pid test_status error_count

  stamp="$(date +%Y%m%d-%H%M%S)"
  run_id="steady-${clients}-${stamp}"
  result_dir="/tmp/loadtest/group-${stamp}"
  report_file="${result_dir}/steady-${clients}-report.json"
  runner_log="${result_dir}/steady-${clients}-runner.log"
  resources_log="${result_dir}/steady-${clients}-resources.log"
  host_log="${result_dir}/steady-${clients}-host-vmstat.log"
  openim_log="${result_dir}/steady-${clients}-openim-errors.log"
  mkdir -p "$result_dir"

  started_at="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
  vmstat 1 >"$host_log" 2>&1 &
  vmstat_pid=$!

  echo "开始测试：${clients} 人"
  echo "结果目录：${result_dir}"

  if "${PWD}/.tmp/bin/groupload" \
      -group "$LOAD_GROUP_PUBLIC_ID" \
      -clients "$clients" \
      -messages "${LOAD_MESSAGES:-100}" \
      -connect-workers "${LOAD_CONNECT_WORKERS:-50}" \
      -interval "${LOAD_INTERVAL:-1s}" \
      -receive-timeout "${LOAD_RECEIVE_TIMEOUT:-60s}" \
      -run "$run_id" \
      -database-url "${LOAD_DATABASE_URL:-postgres://im:im123456@127.0.0.1:5433/im_app?sslmode=disable}" \
      -api "${LOAD_OPENIM_API_URL:-http://127.0.0.1:10002}" \
      -ws "${LOAD_OPENIM_WS_URL:-ws://127.0.0.1:10001}" \
      >"$report_file" 2>"$runner_log"; then
    test_status=0
  else
    test_status=$?
  fi

  kill "$vmstat_pid" 2>/dev/null || true
  wait "$vmstat_pid" 2>/dev/null || true

  docker stats --no-stream \
    --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.NetIO}}\t{{.PIDs}}' \
    >"$resources_log" 2>&1 || true

  docker logs --since "$started_at" "${LOAD_OPENIM_CONTAINER:-openim-server}" 2>&1 \
    | grep -Ei 'error|panic|fatal' >"$openim_log" || true
  error_count="$(wc -l <"$openim_log" | tr -d ' ')"

  if jq empty "$report_file" >/dev/null 2>&1; then
    jq . "$report_file"
  else
    echo '报告不是有效 JSON，请查看程序日志：' >&2
    tail -n 100 "$runner_log" >&2
  fi

  echo '=== 测试后容器资源 ==='
  cat "$resources_log"
  echo '=== OpenIM 异常日志数量 ==='
  echo "${error_count} ${openim_log}"
  echo "测试退出码：${test_status}"
  echo "报告文件：${report_file}"
  echo "资源文件：${resources_log}"
  echo "主机资源文件：${host_log}"
  echo "错误日志：${openim_log}"

  return "$test_status"
}
```

确认函数已经加载：

```bash
type run_group_load
```

### 2000 人压测前检查文件句柄

2000 条 WebSocket 连接会占用至少 2000 个客户端文件描述符。每个新 SSH 终端在执行 1200～2000 人测试前先检查：

```bash
ulimit -Sn
ulimit -Hn
```

如果软限制小于 `10000`、硬限制允许提升，则在当前终端执行：

```bash
ulimit -n 10000
ulimit -Sn
```

如果 `ulimit -n 10000` 报 `Operation not permitted`，说明系统硬限制不足，需要先调整服务器的 PAM/systemd/Docker `nofile` 限制，重新登录后再测试。不要在文件句柄不足的情况下把连接失败误判为 OpenIM 的容量上限。

## 六、可选：一条命令连续测试四档

首次确认每一档都能正常运行后，才建议使用连续模式。每档之间冷却 60 秒；某档失败时立即停止，不继续放大压力。

```bash
for clients in 400 600 800 1000 1200 1400 1600 1800 2000; do
  if ! run_group_load "$clients"; then
    echo "${clients} 人测试失败，已停止后续测试" >&2
    break
  fi
  sleep 60
done
```

## 七、怎么看结果

最重要的字段：

- `requestedClients`：要求建立的在线连接数。
- `connectedClients`：实际成功连接数，必须等于 `requestedClients`。
- `connectionFailures`：连接失败数，必须为 0。
- `successfulMessages`：OpenIM 接受的消息数。
- `messageFailures`：发送失败数，必须为 0。
- `expectedPushes`：理论推送数，正常情况下约等于“已连接人数 × 成功消息数”。
- `missingPushes`：缺失推送数，必须为 0。
- `duplicatePushes`：重复推送数，必须为 0。
- `unexpectedDisconnects`：意外断开数，必须为 0。
- `deliveryLatency`：消息送达延迟分位数，重点看 `p95Ms`、`p99Ms` 和 `maxMs`。
- `pass`：压测程序最终判定。

当前程序的 `pass` 只根据连接失败、消息发送失败、推送缺失、重复推送和意外断开判定，不会因为延迟超过某个数值直接失败。OpenIM 异常日志数量也只是额外诊断信息，不直接决定 `pass`。

快速查看最近一次报告：

```bash
LATEST_REPORT="$(find /tmp/loadtest -type f -name 'steady-*-report.json' -printf '%T@ %p\n' \
  | sort -nr | head -n 1 | cut -d' ' -f2-)"
jq '{requestedClients,connectedClients,connectionFailures,messageFailures,expectedPushes,matchedPushes,missingPushes,duplicatePushes,unexpectedDisconnects,sendAckLatency,deliveryLatency,pass,failureReason}' \
  "$LATEST_REPORT"
```

查看某次测试的程序错误：

```bash
tail -n 100 /tmp/loadtest/group-时间戳/steady-人数-runner.log
```

## 八、哪些情况不能只改人数

以下情况需要先处理，不能直接从 1000 改成 2000：

1. 测试群有效成员不足 2000 人。
2. 新成员只存在业务数据库中，尚未同步到 OpenIM，或者没有真正加入对应 OpenIM 群。
3. `.env` 中的 `OPENIM_SECRET` 缺失或与 OpenIM 服务不一致。
4. 数据库、OpenIM API、WebSocket 地址或容器名发生变化。
5. 更新了 `cmd/groupload` 代码但没有重新编译二进制。
6. 前一档已经出现连接失败、丢推送、重复推送或意外断线。

满足前置条件后，400、600、800、1000、1200、1400、1600、1800、2000 九档使用的是同一套测试逻辑，只有 WebSocket 客户端人数不同。
