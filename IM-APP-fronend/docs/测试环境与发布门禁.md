# 测试环境与发布门禁（可执行方案）

> 背景：热更新曾直发客户 `test` 渠道，导致线上闪退。  
> 目标：用**同机双渠道**先止血，不先上完整第二套 OpenIM。  
> 状态：本文是操作手册；按「落地清单」改代码/打壳后再勾选。

---

## 1. 先搞清楚现状

| 事实 | 说明 |
|---|---|
| 客户装的是「测试 APK」 | 壳内 `VITE_UPDATE_CHANNEL` 实际是 **`test`** |
| 日常发 wgt 默认也是 `test` | `pack-wgt.cjs` 默认 `--channel=test` |
| 服务器同一台 | `8.154.44.197`，业务 API + 热更新记录同一处 |
| 结果 | **一发 wgt = 全体客户下次打开就装**，没有灰度 |

所以问题不是「没有测试」三个字，而是：**开发发布口 = 客户热更新口**。

```text
【现状】
本机 pack:wgt --publish
        │
        ▼
  channel=test（线上）
        │
        ├── 你的手机（若也是 test 壳）→ 更新
        └── 全部客户测试壳         → 更新（事故来源）
```

---

## 2. 目标形态（做完长这样）

| 渠道 | 谁装这个壳 | 谁往这发 wgt | 用途 |
|---|---|---|---|
| **canary** | 仅你自己的内部 APK/IPA | 日常 / 高风险改动 | 真机验收 |
| **test** | 客户现有测试壳（冻结渠道名） | 仅验收通过后 | 给客户 |
| **prod** | 将来正式包（若有） | 正式发版 | 与 test 隔离 |

```text
【目标】
本机日常 ──publish──► channel=canary ──► 只有内部壳能更新
                              │
                         验收通过
                              │
                              ▼
              显式 --channel=test ──► 客户壳才更新
```

后端已按 `platform + channel` 查最新包，**不必先加服务器**；缺的是：

1. 后端允许 `canary` 这个 channel 值  
2. 打一版内部壳（`VITE_UPDATE_CHANNEL=canary`）  
3. 发布脚本默认走 canary，发客户必须显式写 `test`  
4. 文档门禁（本文）

---

## 3. 落地清单（按顺序做，做完打勾）

### 阶段 A：代码与配置（约半天）

- [x] **A1. 后端放开 `canary`**
  - 文件：`IM-APP-server/internal/models/app_release.go`  
    增加常量：`AppChannelCanary = "canary"`
  - 文件：`IM-APP-server/internal/service/app_release.go`  
    `normalizeAppChannel` 增加 `case "canary"`
  - 文件：`IM-APP-server/docs/api-contract.md`  
    `channel` 写成 `canary|test|prod`
  - 部署：代码已改。线上 `im-app-api` 还没更新前，canary 发布接口仍会拒绝。客户 `test` 壳不受影响。

- [x] **A2. 前端识别 canary**
  - 文件：`IM-APP-fronend/src/config.ts`  
    `updateChannel` 支持 `canary` / `test` / `prod`（读 `VITE_UPDATE_CHANNEL`）
  - 文件：`IM-APP-fronend/src/env.d.ts`  
    注释写清三渠道含义

- [x] **A3. 打包脚本默认 canary**
  - 文件：`IM-APP-fronend/scripts/pack-wgt.cjs`  
    - 默认 `channel: 'canary'`  
    - 仅允许 `canary|test|prod`  
    - `--publish` 且 `channel=test|prod` 时打印醒目警告
  - 文件：`IM-APP-fronend/package.json` 增加脚本：
    ```json
    "pack:wgt:canary": "node scripts/pack-wgt.cjs --build --publish --channel=canary --min-native=100",
    "pack:wgt:customer": "node scripts/pack-wgt.cjs --build --publish --channel=test --min-native=100"
    ```

- [x] **A4. 环境变量样例**
  - 新增 `IM-APP-fronend/.env.canary.example`：
    ```env
    VITE_API_BASE_URL=http://8.154.44.197/api/v1
    VITE_UPDATE_CHANNEL=canary
    ```
  - 客户壳继续用（或不写）`VITE_UPDATE_CHANNEL=test`，**不要**把客户壳改成 canary

### 阶段 B：打内部 canary 壳（必须真机，约半天含云打包）

> wgt 换不了「壳里写死的 channel」。内部验收必须另打一版 APK/IPA。

- [ ] **B1. 准备 canary 环境文件**  
  复制 `.env.canary.example` → `.env`（或打包前临时写入），确认：
  ```env
  VITE_API_BASE_URL=http://8.154.44.197/api/v1
  VITE_UPDATE_CHANNEL=canary
  ```

- [ ] **B2. HBuilderX 打自定义基座 / 云打包**
  1. 打开 `IM-APP-fronend`，确认 OpenIM 原生插件已勾选  
  2. **发行 → 原生 App-云打包**（或制作自定义调试基座）  
  3. `versionCode` 可仍为 `100`（与客户壳一致即可，靠 **channel** 隔离，不靠 versionCode）  
  4. 产出 **仅自己安装** 的 APK（及需要时的企业签 IPA）  
  5. 手机安装后打开「关于我们」或抓一次更新检查请求，确认 query 里 `channel=canary`

- [ ] **B3. 自测壳是否串包**
  1. 对 canary 发一个小版本 wgt（见阶段 C）  
  2. **只有** canary 壳弹更新  
  3. 客户 test 壳（或另一台仍装客户包的手机）**不弹**  
  不满足则停，查壳是否打错 channel

### 阶段 C：日常发布流程（从此固定）

#### C1. 日常开发（只发内部）

```bash
cd IM-APP-fronend
npm run pack:wgt:canary -- --changelog=这里写自己能看懂的说明
```

或：

```bash
node scripts/pack-wgt.cjs --build --publish --channel=canary --min-native=100 --changelog=…
```

#### C2. 发客户前门禁（必须勾完）

**① H5 冒烟**（`npm run dev:h5`）

- [ ] 登录 / 进群  
- [ ] 发一张图  
- [ ] 翻历史时来一条新消息，列表不乱跳  
- [ ] 杀进程再开，能进会话  

**② canary 真机**（装内部壳的那台）

- [ ] 划掉 App 冷启动，不闪退  
- [ ] 进群聊、发图、翻历史  
- [ ] 有华为/鸿蒙再测一台（发图 / content://）  
- [ ] 高风险改动（见下）禁止跳过本步  

**③ 再发客户渠道**

```bash
cd IM-APP-fronend
npm run pack:wgt:customer -- --changelog=客户能看懂的更新说明
```

或显式：

```bash
node scripts/pack-wgt.cjs --build --publish --channel=test --min-native=100 --changelog=…
```

#### C3. 高风险改动（禁止跳过 canary）

出现下列任一，**必须** canary 真机冷启动通过后再发 `test`：

- 读写本地文件 / `uni.storage` 大批量数据  
- 启动或进房时批量下载媒体  
- 改 OpenIM 登录 / 同步 / 进房首屏  
- 改原生路径、选图、鸿蒙兼容  
- 任何你不确定会不会闪退的逻辑  

### 阶段 D：客户侧说明（可选但建议）

- [ ] 客户继续用现有 test 壳，**不用重装**（渠道名仍叫 test）  
- [ ] 你自己手机装 canary 壳；勿把 canary APK 发给客户  
- [ ] 出事故回滚：再发一版「去掉问题逻辑」的 wgt 到 `test`（与现在回滚方式相同）

## 4. 命令速查

| 目的 | 命令 |
|---|---|
| 只打 wgt 不上传 | `npm run pack:wgt -- --build` |
| 发内部验收 | `npm run pack:wgt:canary -- --changelog=…` |
| 发客户（门禁通过后） | `npm run pack:wgt:customer -- --changelog=…` |
| 正式包渠道（若有 prod 壳） | `npm run pack:wgt -- --build --publish --channel=prod --min-native=100 --changelog=…` |

`--min-native` 必须 ≤ 目标壳的 `versionCode`（当前客户壳一般为 `100`）。

## 5. 本机日常怎么测（不发 wgt 也能挡一半）

| 场景 | 怎么测 | 够不够 |
|---|---|---|
| 文案、布局、大部分业务逻辑 | `npm run dev:h5` | 够做初筛 |
| 鸿蒙发图、闪退、热更新、原生插件 | **canary 真机** | H5 不算数 |
| 后端接口 | 现网或本地 Go | 与渠道无关 |

H5 验证可参考仓库技能 `im-h5-verify`，**不能替代** App 冷启动。

## 6. 后续增强（有余力再做，非本期）

### 6.1 同机第二套业务 API（中成本）

- 同一台机再起一个 `im-app-api` + 独立 Postgres 库/schema（端口或路径区分）  
- OpenIM **先共用**现网  
- 适合：注册登录、群设置、公告、热更新发布本身  
- 不适合单独证明：消息库压力、OpenIM 升级  

### 6.2 完整 Staging（高成本）

- 独立 VPS 或同机完整第二套：OpenIM + Mongo + MinIO + 业务库  
- 内测壳 `VITE_API_BASE_URL` 指向 staging  
- 仅在大重构 / OpenIM 升级 / 数据迁移频繁时值得  

**本期明确不做**：K8s、蓝绿、管理后台灰度。

---

## 7. 验收标准（方案是否「可执行且生效」）

同时满足才算落地成功：

1. 发 `canary` wgt 后，**仅**内部壳弹更新，客户壳不弹  
2. 发 `test` wgt 后，客户壳弹更新（与现在一致）  
3. 团队习惯变成：日常只跑 `pack:wgt:canary`；发客户前勾完门禁  
4. 再出现高风险改动时，客户不会在「第一次真机验证」时中招

## 9. 当前分支怎么用

`feat/chat-image-speed` 的发布默认是 **canary**。客户现在的测试壳仍请求 `channel=test`，所以这个分支打出来的 wgt **不会**装进客户手机。

阶段 A 的代码已经改完。还差两步才能在自己手机上收到 canary 包：

1. 把含 `canary` 校验的 `im-app-api` 部署到 `8.154.44.197`。不部署的话，发布接口会拒绝 `canary`，客户渠道不受影响。
2. 用 `.env.canary.example` 打一版只自己安装的 APK/IPA（阶段 B）。wgt 改不了壳里的渠道。

在内部壳装好之前，不要跑 `pack:wgt:customer`。
