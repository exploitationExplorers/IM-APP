# 原生媒体优化：本轮实施与验证

日期：2026-11-13。本轮交付聚焦已明确反馈的“历史旧图加载慢／怀疑反复下载”，对应方案 P0 的本地诊断与 P1 的 Android 媒体管线。后端与生产部署未修改，聊天 UI 与 OpenIM 消息库、Outbox、retention／purge 继续使用现有规则。

## 已落地的代码

Android 图片加载改为 Coil 2.7.0 + OkHttp 4.12.0。有界内存／磁盘缓存、HTTP 缓存策略、请求取消与网络读取交给成熟库；下载地址与缓存身份分开，消息 UI 通过原 `RemoteMediaImage` 入口接入。

| 改动 | 实际行为 |
| --- | --- |
| 稳定、隔离的缓存身份 | 环境与账号参与命名空间；受控对象临时签名变化可复用；未知域名、业务 token、规格、版本、重复参数语义保持隔离 |
| 图片与文件分开调度 | 图片最多 4 个任务，头像最多占其中 1 个；文件导出另设 2 个槽。取消会传递至下载，无消费者的离屏任务不继续占队列 |
| 相同图片合并工作 | 同身份同尺寸的多个消费者共享在途下载／解码；一个消费者取消不误取消仍在使用的消费者；动画实例各自持有播放状态 |
| 缓存命中出图 | Compose 初始化可直接取内存缓存；不再先清空已有 visual 再查缓存；磁盘用 Coil journal 管理，图片完成后不逐张全目录扫描 |
| 下载与内容保护 | HTTPS、不携带业务认证头／Cookie、限制字节、禁止 HTTPS 降级；遵守最终图片的 HTTP 缓存策略，坏图缓存移除后可重试 |
| 诊断 | 有界记录 QUEUE／HEADERS／FETCH／DECODE／缓存层／取消／帧调度及实际响应体字节；不记录原 URL、账号、对象路径或签名，可随原“调试资讯”导出 |
| 规格与动画 | 继续 snapshot 优先与既有 URL 缩图策略；GIF 保留动画、页面离开／离屏停止，原图保存保持独立职责 |

`FRAME_SCHEDULED` 是 Compose 数据就绪后调度帧的采样，不能当成光学测量到的首个像素。网络响应体统计来自本进程下载，不是 CDN 厂商账单。当前调度使用头像限流和取消腾出资源，没有下载全部历史，也没有新增远处历史预取。

iOS 已同步环境／账号／资源／规格身份，未知签名与 capability token 保真；加入线程安全内存命中入口、同下载完成后避免重复解码、退出时取消旧会话任务及清理内存。磁盘维护从逐图扫描改为按数量、字节和时间触发；仍保留既有文件保护和容量／有效期规则。本轮沿用现有 URLSession／ImageIO 实现，尚未切换 SDWebImage；是否迁移须在 Mac 上完成依赖、动画与性能兼容验证后决定。

## 本地验证范围

固定源码、最终 APK SHA、构建／设备原始输出及汇总见[验证清单](../../.native-cache/verification/media-20261113/verification.json)；最终结果以清单为准。构建包含 Android 134 项单元测试、主包、测试包与 Lint，设备验证使用专用模拟器。

最终交付为 [Android 0.3.1-media 测试包](../../.native-cache/deliverables/IM-Android-0.3.1-media.apk)，97,506,783 字节（约 93 MiB），versionCode 为 5。SHA-256：`a3a05bf9a25310c3abfb4011530704d31bf4405a21de0bedc911ae3e1ba970a6`。设备安装包与交付包 SHA 一致；151 个冻结构建输入已核对。134 项单元测试全部通过，Lint 为 0 个错误、45 个警告，警告尚未全部清理。媒体、重启、SDK、Keystore、GIF、14 个合成页面与无凭据登录入口检查均通过；已人工查看聊天图片及登录页截图。

受控图片测试运行于模拟器内部的 loopback HTTPS 服务，证书信任只注入测试入口；没有向生产账号或参考软件服务发请求。覆盖：首次取图、内存命中、磁盘命中、签名轮换、加载器重建、账号隔离、8 个并发消费者只传一份、取消部分消费者、取消最后消费者释放连接、no-store、302 与最终内容缓存、坏图恢复。另在强制结束进程后重新启动测试，禁止网络仍能从磁盘读取。

首次运行受控服务时，模拟器网络状态被系统标为离线，测试入口改为只在测试中关闭网络状态观察；生产仍使用默认网络观察。页面回归曾受模拟器 System UI 无响应弹窗遮挡：真实窗口不可见时动图按设计停止；关闭弹窗、恢复焦点后重跑，没有放宽产品可见性判断。动画包装器实例分配也已改为独占，避免复制播放配置。

页面／SDK 回归继续检查 AndroidKeyStore、无凭据 OpenIM 初始化与反初始化、合成图片与 14 个页面；这些不能证明真实账号互通或完整像素一致。iOS 运行 8 项工程静态检查和 Swift 语法解析；Swift XCTest、Xcode 编译和 iPhone 性能不在 Windows 上声称通过。

## Android 怎么验证你反馈的旧图

安装本轮 `IM-Android-0.3.1-media.apk`。与上一份测试 APK 使用相同 staging 应用 ID 与调试签名，可作为该测试版的更新；它不是现有 uni-app 正式版的原位升级包。

1. 登录原有账号，选择同一个历史聊天，固定观察约 20 张旧图片。首次升级使用新的隔离缓存，不直接复用旧手写缓存目录，第一次可能仍需下载。
2. 等图片加载完成后，退出会话再进入相同位置，观察图片是否直接出现。有效缓存、同规格和权限允许时，不应再次传输整图。
3. 强制关闭 App 后重新打开，再进入同一位置，验证磁盘缓存；确认消息本身已可见后，可断网检查图片，避免把登录／消息同步失败误判为图片缓存失败。
4. 在原“调试资讯”页面保存或复制诊断。对比相同进程内的媒体响应体累计字节与 `MEMORY_CACHE`／`DISK`／`NETWORK` 等记录；杀进程后累计计数会重置。诊断页既有 API／WS 探测流量不属于图片整图流量。
5. 若第二次仍取图，保留大概时间、是气泡还是全屏预览、是否清过缓存、是否切号或更换环境。不要发送完整签名 URL／Token。气泡、预览和原图属于不同规格，首次切换规格可能合法下载。

不要把缓存清理、容量淘汰、内容更新、服务器 no-store／重新验证要求或新规格取图，统称为“缓存失败”。本轮保留 HTTP 缓存约束，避免通过无条件永久缓存掩盖权限或过期问题。

## 朋友的 Mac 怎么验证

使用本轮 `IM-iOS-0.3.0-media-mac-check.zip`，解压后先按 `README-Mac.md` 运行 `bash IM-APP-ios/scripts/verify_on_mac.sh`。脚本执行共享核心 XCTest、工程检查、Pods 安装与未签名模拟器构建；不会发布。

[下载 Mac 源码验证包](../../.native-cache/deliverables/IM-iOS-0.3.0-media-mac-check.zip)。此包是源码快照，不是可安装的 IPA；工程仍为 0.3.0／build 4。Windows 上已通过 8 项工程静态检查，29 个 Swift 文件语法解析无错误；这不能替代 Swift 类型检查、XCTest 或 Xcode 构建。

新增的 `MediaCacheIdentityTests` 验证签名轮换、未知域名、token、账号、环境、参数顺序、规格／版本与编码路径隔离。编译通过后再用 iPhone 依照上面的旧图三轮测试，追加快速滚动、页面切换、前后台、切号、退出、清缓存与内存压力检查。诊断摘要包含 iOS 缓存层采样；目前没有 Android 同等粒度的 iOS 网络字节测量，不能据此替代抓包或 Instruments。

## 后续阶段的明确边界

本轮不将全部性能方案标为完成。仍需真实慢图样本确认 `/object/` 的缩图参数是否生效、最终尺寸／字节、CDN 路由与命中，以及真实网络下的 P50／P95；本地服务性能数字不能作为生产指标。

如数据证明存储交付有问题，再按方案 P2 增加可信旧路径解析或派生图并灰度；当前没有改后端，也没有改线上消息内容。iOS P3 需要 Mac／iPhone 编译与运行验证。P4 的持久上传任务、本地上传中气泡、压缩与上传恢复尚未实施，本轮没有把未持久化的本地占位伪装为 SDK 已发送消息。

正式签名、发布与生产用户灰度仍受原方案门禁约束；本轮提供本地测试 APK 和 Mac 源码验证包。
