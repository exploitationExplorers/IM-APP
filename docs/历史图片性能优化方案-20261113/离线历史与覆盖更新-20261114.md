# 本地历史、图片缓存与覆盖更新

本轮针对更新后“读取历史中…”和旧图片长时间转圈，交付 Android 内测版本 `0.3.5-offline`（versionCode 9）。已完成本地构建和模拟器验收，真实账号与 iPhone 结果仍待实测。

## 原因与调整

| 问题 | 已确认原因 | 调整 |
| --- | --- | --- |
| 冷启动等联网 | 原先先请求 `/me`，再申请 `/im/token`，最后才打开 SDK | Android Keystore / iOS Keychain 保存绑定账号、环境的 SDK 登录票据；本机资料和 SDK 开库先行，资料校验后台进行 |
| 本地记录也等很久 | OpenIM 高级历史接口先查本地，再可能同步补齐序号缺口 | 普通文字、图片、视频等通过官方纯本地搜索先显示；完整高级历史独立后台补齐，不占本地翻页的 loading |
| 一直自动读下一页 | 列表每次 loading/消息条数变化重建历史观察 | 按会话稳定观察，仅实际滚动到边界请求一页，首屏不连扫全库 |
| 旧图片转圈 | 先尝试首个网络地址，后面的已有缓存还要等；过期磁盘缓存先联网校验；本地解码排在网络队列后 | 所有候选先查本账号缓存，原 URL 仅作为旧缓存候选；本地解码使用独立并发槽，已有有效字节先显示 |
| 断网群历史不出 | 已检查且返回空水位的群只在内存记住检查结果 | 持久保存已核对群的事实；未知边界仍要联网核对，保留群历史水位与成员清理规则 |

聊天数据库和图片文件是不同数据。消息在库里有图片 URL，不代表图片文件已经下载。已保存且未被用户清理或系统回收的图片可以离线显示；从未下载、损坏或已经回收的图片需要联网。

## 本地分页和 SDK 边界

首屏及后续本地页每次最多读取 40 条，固定打开会话时的时间范围，按消息 ID 合并去重。联网补洞有独立状态、游标和超时，失败保留当前已显示消息，不删除或重建 SDK 数据库。

固定 Android Core 的 `searchLocalMessages` 内部仍会过滤部分类型，明确可用的本地预览为 101–110 和 114，共 11 类：普通文字、图片、语音、视频、文件、提及、合并、名片、位置、自定义和引用。表情、部分高级文本、系统通知等继续由完整高级历史接口补齐。因此本地搜索短页只表示该预览读尽，不能当成完整历史结束；完整结束状态只认高级接口的 `isEnd`。当前不能承诺所有类型在任意 SDK 补洞状态下都能离线立即显示。

iOS 使用固定 SDK 的公开接口；上游 Core 源码仅作对照，Windows 的语法检查不能证明所链接 Apple 二进制运行行为。

SDK 本地登录成功与服务器在线认证是两件事。加密旧票据可用于尝试恢复本机库，不延长票据有效期；明确认证拒绝仍撤销本机认证，SDK Token 失效仍禁发，不假造 ACK，也不把“待核对”改成发送成功。

## 升级和用户验证

1. 直接覆盖安装新版，保留原应用、数据与账号；不要卸载旧版或清除应用数据。
2. 从旧 `0.3.4-media` 首次迁入时联网一次，让新版保存加密 SDK 票据。旧版没有该票据，不能凭空保证第一次升级就能断网冷启动。
3. 打开几个已有文字、图片、视频的会话，确认旧图片已实际显示；向上翻页，确认不会一次读完全部历史。
4. 完全退出应用，关闭网络，重新打开；检查会话、普通历史和已缓存图片。未下载图断网时不能显示属于文件尚未在本机。
5. 恢复网络，检查增量消息与完整类型回填，不重复发送待核对消息。
6. 群聊另检查历史清理、成员清理和未知群边界，不能因离线优化恢复已被隐藏的历史。
