# 发送核对与多人视频转发修复

用户确认：图片是 Android `0.3.5-offline` 刚发出的，视频转发选择了 4 个人。本轮 Android 版本为 `0.3.6-forward` / versionCode `10`，保留原 staging 包名和签名，直接覆盖安装。

## 已确认的客户端缺口

1. 所有 SDK 发送错误原来都进入 `UNCERTAIN`。固定 Core 的本地参数、资源和群信息校验拒绝发生在网络提交前，应显示失败并允许用户检查后手动重试；网络超时、未知错误与重复消息 ID 仍然不能据此重发。
2. 固定 Core 的发送状态会通过会话 `latestMsg` 更新。客户端原来只从新消息与历史渠道消费成功证据，会话更新未处理；重连和回前台也没有主动复查未决消息。
3. 文字和图片有客户端直接转发路径，视频没有；即使只选 4 个收件人也交给服务端批量任务。Android 视频转发快照还将格式写死成 `mp4`，丢弃视频和封面的 UUID。

截图没有提供 SDK 数字错误码，当前没有测试账号或该手机日志，因此不能断言它此次具体是哪个拒绝、网络错误或服务器任务错误。以下是对已确认代码缺口的修复，真实账号需复测。

## Android 调整

已知本地拒绝保留为失败，查询不到本地记录时不再把这一失败事实改回未知。用户手动重试仍先按同一个消息 ID 查询，防止迟到成功后重复发送。未知错误、网络超时、重复 ID 保留待确认，不伪造发送成功。

会话最新消息中与本账号、同目标、同消息 ID 对应的成功证据可以结束待核对。重连、同步完成、回前台和打开会话时静默复查；后台查询不反复弹出截图里的长提示，点击核对时使用简短居中提示。

手选 1～12 个明确收件人的普通文字、图片、视频使用客户端直接转发：检查目标权限，每个源媒体仅归档一次；每个收件人创建并持久保存独立 SDK ID，各收件人独立等待真实 SDK ACK。成功对象不重发，未决对象只核对。超过 12 个、标签和全部好友仍走现有服务端批量任务，本轮未改服务端或其存储限制。

视频保留真实容器格式、视频/封面 UUID、远程地址和尺寸，剥离原设备路径；封面缓存按账号复用。视频或封面尚未有远程地址时在提交前明确提示，不能把本地路径发送给别人。结果不明时不提示“转发成功”，也不提示用户直接重复整批发送。
