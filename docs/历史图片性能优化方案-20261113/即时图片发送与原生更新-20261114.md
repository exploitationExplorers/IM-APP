# 图片发送、转发与原生更新：2026-11-14

本轮针对用户提供的 4 张截图继续实施原方案 P4。Android 目标版本为 `0.3.3-media` / code `7`，iOS 为 `0.3.0` / build `4` 的本轮源码快照。旧 uni-app 仍是功能与 UI 基准；对照 66 是为了检查媒体处理方式，不替换原 UI。

## 已确认的原因与实施

Android 原发送流程在业务接口上传全部结束后才创建 SDK 消息和 Outbox，所以本地有图仍要先等网络，UI 还显示“附件上传中”。现改为先保存本账号本地媒体任务、显示本地图气泡，在气泡内展示 loading，再在后台上传和交接 SDK Outbox。上传前任务不是 SDK 已发送消息，不会提前打勾。失败保留任务供手动重试，恢复时沿用已保存的 SDK 消息 ID，不能重建另一条重复消息。

iOS 原生 SDK 已支持本地文件上传，但旧流程在持久化及显示气泡前等待群权限 HTTP。现将气泡持久化与发布前移，发送前仍保留真实权限检查。成功后将已验证的账号私有图片与远端地址绑定，列表、点击预览和保存优先复用本机文件。

Android 原转发在选择页串行解析接收目标、保留图片副本、逐条等 ACK，等待时间随人数增长。本轮将转发消息快照、目标和固定幂等键先保存为本地任务，再返回聊天；后台做前置检查和发送，不同目标可同时等待回执，同一目标的消息保持顺序。iOS 同样先保存已有幂等批次再由账号 service 持有后台请求，页面退出不会丢掉批次。

选择页离开代表“已加入发送”，不是“接收方已收到”。消息气泡和转发记录继续显示真实结果；失败或不确定结果可在任务记录中恢复、核对。对于已经尝试发送但结果未知的 SDK 消息，只核对、不盲目重发。不能通过隐藏“提交中”或提前提示“转发成功”冒充性能改进。

转发图片已有内容优先复用：Android 为 preserve 返回的同规格新 URL 建缓存映射；批量转发通过已有 `forward-task-progress` 的原会话、原消息 ID 和归档 snapshot 精确关联。iOS 通过同类证据关联。只复用确定属于同一张图、同一种规格的内容，不把缩略图当成原图，不按时间或尺寸猜图，不绕过账号和可见性规则。没有缓存的图片首次仍需真实下载。

## 原生更新分发

Android 已接独立 HTTPS `update.json`，配置后启动每进程检查一次，也可在“关于我们”手动检查。有新版才提示，下载校验包名、版本、原生标识、签名、大小和 SHA-256 后由系统安装。更新使用独立 `native-staging` 渠道，不写旧 uni-app 的发布记录。

iOS 配置真实 TestFlight／App Store 地址后从应用入口打开相应渠道。下载站生成器、稳定签名配置和手动 CI 已准备，默认不部署。固定托管 URL、Apple 邀请链接与发布凭据尚未提供，所以本轮不会产生可用的线上下载站或 TestFlight 包；这不影响本地聊天修复与 APK 验证。

详细配置、打包、上传顺序与更新步骤见 [原生分发与更新操作](../原生分发与更新操作.md)。本轮交付安装一次后，后续要使用自动检查仍需先将真实独立分发地址编入包并发布。

## 同日后续：表情、转发和视频反馈

后续 Android 版本为 `0.3.4-media` / code `8`。本轮查明图片转发快照将必填 `PictureInfo.Type` 留空，现按旧 uni-app 规则补齐原图、大图、缩略图的类型，保留各自 URL、UUID 和尺寸。旧版明确失败任务沿用原 SDK ID 修复；结果不明的任务仅核对。普通聊天和转发页去掉任务进度入口及开发文案，真实 ACK 全部成功或服务端匹配任务全部完成后才提示“转发成功”。

表情切换明确收起键盘并清焦点，让面板占用自己的布局空间。视频按封面宽高用同一缩放因子限制尺寸，竖视频不再被独立最小宽度撑成横卡；中心播放图标和时长保持可见。点击气泡直接准备并播放，避免第二次点击和封面重试拦截。已知旧签名视频仅按受限规则恢复稳定入口，未知签名保持原样；未获得原用户视频 URL，不能把过期签名认定为该用户播放失败的唯一原因。

REA 本轮证据索引为 `.analysis/media-parity-fix-20261114/evidence-index.json`：竞品表情控制器切 `EMOJI` 模式、收键盘并清焦点；视频气泡统一使用封面和时长；详情以 ExoPlayer 准备后自动播放。当前采用平台播放器实现相同点击行为，静态观察不代表竞品或我们的真机耗时已测。

## 同轮追加：菜单、短提示与录像本地回显

按旧 uni-app 的菜单实现逐项核查，继续使用现有收藏、表情、撤回、群管理及 OpenIM 会话/消息接口。Android 自己的消息不因初次回调缺少 seq 就隐藏撤回，执行时先查询 SDK 本地消息及最近历史取得正式 seq；仍无 seq 时不提交，服务端超时和权限拒绝保持真实失败。共享置顶的网络权限检查移到业务线程，避免阻塞聊天串行处理。iOS 修复自己的消息无法多选撤回，以及保存/加入表情忽略已保存本机原图的问题。准备草稿或结果未知的消息不允许转发、收藏或引用。

普通操作成功/错误统一在窗口中间显示约 3 秒后消失，移除顶部固定提示。真实禁言、连接和置顶状态继续保留；需要决定的删除、撤回等确认框保留。

Android 录制确认后，先将 App 自己生成的录像移动到账号私有持久任务，再显示本地视频气泡。封面、时长和上传均在后台处理；原视频上传成功而封面失败时，重试复用已传视频。交接消息时沿用一个持久 SDK ID，ACK 后按账号私有索引保留视频和封面，本机刚发视频优先本地播放。iOS 在媒体选择返回时先显示仅用于 UI 的准备占位，后台复制和提取封面，真实 Outbox 落盘后接管；占位不代表发送成功。

本轮源码覆盖这些链路，最终验证结果仍以对应 verification.json 为准。模拟器的合成录像与阻塞上传回归不能代替华为系统相机、原始视频编码、真实账号收发与接收端验证；约 1 秒封面和“无需加载”的真机体验需分别计时，不能凭静态代码承诺固定耗时。
