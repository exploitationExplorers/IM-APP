# 群聊消息已读 —— 后端改造清单

> 只列 Go 后端(IM-APP-server)需要动的地方,按实施顺序排列。
> 前置背景见《群聊消息已读实现方案.md》。核心思路:后端读每个群成员的 `hasReadSeq`,`成员.hasReadSeq >= 消息.seq` 即视为该成员已读。

## 2. OpenIM 客户端(`internal/im/client.go`)

### 2.1 新增 `GetConversationHasReadSeq`

仿照现有 `postWithAdmin` 写法(参考同文件 `GetConversations` L599、`MarkConversationAsRead` L682):

```go
// GetConversationHasReadSeq 查询某个用户在某条会话上的已读游标。
// 用户从未打开该会话(或无会话记录)时 hasReadSeq 为 0,视为未读。
func (c *Client) GetConversationHasReadSeq(ctx context.Context, userID, conversationID string) (int64, error) {
	var data struct {
		Seqs map[string]struct {
			HasReadSeq int64 `json:"hasReadSeq"`
		} `json:"seqs"`
	}
	if err := c.postWithAdmin(ctx, "/msg/get_conversations_has_read_and_max_seq", map[string]any{
		"userID":         userID,
		"conversationIDs": []string{conversationID},
	}, &data); err != nil {
		return 0, err
	}
	if seq, ok := data.Seqs[conversationID]; ok {
		return seq.HasReadSeq, nil
	}
	return 0, nil
}
```

> 该 REST 端点 `GetConversationsHasReadAndMaxSeq` 已核实存在于社区版服务端(`internal/api/msg.go`),返回 `{ seqs: { conversationID: { hasReadSeq, maxSeq, maxSeqTime } } }`。

## 3. 服务方法(`internal/service/im.go`)

新增方法,挂在现有 `IMService`(L76)上,复用其 `Client` 与 `TokenCache`:

```go
// MessageReadStatus 计算"某群会话里若干消息各自被哪些成员已读"。
// 入参 conversationID = "sg_<imGroupId>";messages 来自发送者自己的消息。
func (s *IMService) MessageReadStatus(ctx context.Context, callerUserID, conversationID string,
	messages []MessageReadQuery) (map[string]MessageReadResult, error)
```

内部流程:

1. **入参 → OpenIM 群 ID**:`conversationID` 以 `sg_` 前缀去掉即 `imGroupID`;调 `im.UserIDFromBusinessID` 还原校验(不合规直接报参数错误)。
2. **校验调用者是群成员**:`ListGroupMembers(imGroupID)` 里必须包含调用者的 OpenIM userID(`im.UserIDFromBusinessID(callerUserID)`),否则返回 403。
3. **拉一次全量成员 + 游标**(只做一次,供下面所有消息复用):
   - `members = ListGroupMembers(imGroupID)`;
   - 对除调用者外的每个成员并发调 `GetConversationHasReadSeq(imUserID, conversationID)`,并发上限 10(golang.org/x/sync 已在依赖里),失败重试 1 次后跳过该成员。
4. **逐条消息计算** 已读/未读:
   - 已读池 = `members` 中 `joinTime <= 消息.sendTime` 的成员(晚于消息发送才入群的不计);
   - 已读 = 池内 `hasReadSeq >= 消息.seq`;
   - `hasReadCount`/`unreadCount`/`totalCount` 均在此池内计数,**始终排除调用者本人**;
   - `readMemberIds` 返回已读成员的 OpenIM userID(前端自行还原业务 UUID 与昵称头像)。
5. **结果按 `clientMsgID` 返回**,便于前端直接贴到消息上。

结构定义:

```go
type MessageReadQuery struct {
	ClientMsgID string `json:"clientMsgId"`
	Seq         int64  `json:"seq"`
	SendTime    int64  `json:"sendTime"` // 毫秒
}
type MessageReadResult struct {
	TotalCount   int      `json:"totalCount"`   // 应读人数(不含发送者)
	HasReadCount int      `json:"hasReadCount"`
	UnreadCount  int      `json:"unreadCount"`
	ReadMemberIDs []string `json:"readMemberIds"` // OpenIM userID
}
```

### 4.2 Handler(`internal/handler/im.go`,仿照现有 `RecallMessage` 写法)

```go
func (h *IMHandler) MessageReadStatus(c *gin.Context) {
	var req struct {
		ConversationID string `json:"conversationID" binding:"required"`
		Messages       []service.MessageReadQuery `json:"messages" binding:"required,min=1,max=50"`
	}
	if err := c.ShouldBindJSON(&req); err != nil {
		response.Fail(c, http.StatusBadRequest, "参数不正确")
		return
	}
	results, err := h.Service.MessageReadStatus(c.Request.Context(),
		middleware.UserID(c), req.ConversationID, req.Messages)
	if err != nil {
		// 复用 handleIMError(c, err) 的错误映射
		h.handleIMError(c, err)
		return
	}
	response.OK(c, results)
}
```

## 5. 缓存(复用现有 Redis 能力)

用 `IMService.TokenCache`(L82)同款的 `CacheGet/CacheSet`,新增两个 key:

| key | 值 | TTL | 说明 |
|---|---|---|---|
| `im:read:cursor:{conversationID}:{userID}` | hasReadSeq | 3s | 成员游标,单调递增,可安全复用 |
| `im:read:status:{conversationID}:{seq}` | 结果 JSON | 8s | 整条消息的已读结果 |

命中 `status` 缓存直接返回,未命中才拉成员游标。一次请求内多个 seq 共享同一次成员游标拉取。

## 6. 计算规则(实现时必须遵守)

1. **已读判定**:`成员.hasReadSeq >= 消息.seq`(OpenIM 会话内 seq 单调递增;`hasReadSeq` 即该成员读到的最大 seq)。
2. **排除发送者本人**:`hasReadCount / unreadCount / totalCount` 都算"除发送者外的其他成员"。
3. **发送后才入群的成员**:`成员.joinTime > 消息.sendTime` 的不计入总数(既不算已读也不算未读)。
4. **退群成员**:不参与计算(直接取当前成员列表)。
5. **从未打开过会话的成员**:OpenIM 无游标 → `hasReadSeq=0` → 未读。

---

## 7. 不需要动的(刻意不做)

- **OpenIM 服务端**:不改镜像、不改配置、不开 `afterGroupMsgRead` webhook(该回调不含会话 ID,无主链路价值)。
- **数据库**:不加表(游标读 OpenIM、结果只进 Redis)。
- **.env**:无需新增配置。
- **现有接口 / 单聊已读**:不动(单聊已读前端用 `isRead` 字段即可,与本需求无关)。
- **消息 seq 落库**:不需要(前端 SDK 消息自带 `seq`,直接传入)。

## 8. 验收(后端视角)

```bash
# 正常:发送者是成员
curl -X POST http://127.0.0.1:8080/api/v1/im/messages/read-status \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"conversationID":"sg_<imGroupId>","messages":[{"clientMsgId":"a1","seq":100,"sendTime":1720000000000}]}'
# → totalCount=成员数-1,hasReadCount 随成员打开会话递增(≤5s 缓存失效后重新计算)

# 非群成员:返回 403
# 参数缺失 / seq 异常:返回 400
# 群 50 人:缓存命中时 <100ms;未命中(并发拉游标)<1s
```
