# iOS 原生开发约束

适用于本目录全部 Swift、Objective-C、Swift Package、测试及工程配置。修改前必须阅读并遵守：

- [iOS 原生开发代码与架构规范](../docs/iOS原生开发代码与架构规范.md)

## 必须执行

1. UIKit 负责展示，业务规则、流程编排和 SDK/存储适配分清职责；新增业务不得默认堆入 NativeIMService 或 NativeConversationViewController。
2. UI 状态遵守 MainActor 隔离；异步工作明确 owner、取消与错误处理，回写前检查账号代次和请求身份。
3. SDK 只有一个 owner，SDK 独占历史库；禁止靠清库修复问题。Outbox 先持久化后发送，发送未知结果先核对，不能盲目重发。
4. SDK/旧消息字典在边界规范化，兼容 camelCase / PascalCase；不改写未知媒体签名 URL，不假定 Web SDK 能力适用于原生。
5. 禁止吞错、假成功、强制转换掩盖类型问题、主线程重任务和无界资源使用；新增代码不得扩大原有架构债务。
6. 按变更风险执行工程检查、核心测试、模拟器或真机验证；只报告实际执行的结果。
7. 不因重构、格式化或打包需求顺手解除 Release/Archive 门禁；发布配置按专门流程处理。
8. 涉及 OpenIM 的功能，修改前先阅读官方 iOS 对应功能文档，再与 Podfile.lock 固定版本的正式头文件/实现核对；记录文档路径、版本差异与验证结果。不得仅按 Android/Web 接口猜测 iOS 能力。

现有大文件采用渐进拆分；函数/文件行数仅作为审查信号。不要为小修复全量搬迁、引入无用抽象或重写稳定模块。具体边界、例外、验证命令和审查清单以链接文档为准。
